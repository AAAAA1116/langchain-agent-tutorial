# Python 作用域与导入

## 1. 不要直接 `python 包内文件.py`

运行时起点会钻进包里面（`sys.path[0]` 变成文件所在目录），包名这层就看不见了。
包内文件要用模块方式运行：`python -m 包.模块`。

## 2. 包内模块之间统一用绝对导入

`from 包名.模块名 import ...`，写绝对路径就对了，不要混用相对导入。

## 3. 项目变大后用 `pip install -e .`

它做的事：在项目根写一个 `pyproject.toml` 声明包名，然后 `pip install -e .` 装一次——
等价于把整个项目当成一个"已安装的第三方库"，效果是把项目根目录永久注册进虚拟环境的
`site-packages`（通过 `.pth` 文件），而改源码立即生效，不需要重装。

比 `sys.path.append("..")` 好在哪：

- **不依赖工作目录**：`append("..")` 指向哪儿取决于"从哪个目录启动脚本"，换目录、换机器、
  部署后就坏了；可编辑安装注册的是绝对路径，任何地方启动都能 `import`。

## 4. 文件名不要和标准库/第三方包同名（遮蔽）

自己新建的文件`random.py` 。运行 `python random.py` 时，
脚本所在目录 `sys.path[0]` 排在标准库前面，`import random` 先匹配到自己这个同名文件
（即"遮蔽"），拿到的不是标准库。

修复：改个名。排查：`print(模块.__file__)` 看实际导入的是哪个。

## 5. 两个必背的命令行选项 `-m` / `-c`

- `-m`：按包路径运行模块（module = 模块）。如 `python -m pip install ...`、`python -m tools.weather`。
  两个用途：跑包内文件（对应规则 1），以及让 `pip` 一定装进当前这个解释器（解决装包和运行不是同一个 Python 的 bug）。
- `-c`：执行引号里的单行代码（command）。如 `python -c "import random; print(random.__file__)"`，临时验证用。

## 6. 类变量在推导式里看不到（LEGB 与类体）

```python
class A:
    n = 3
    items = [n * i for i in range(3)]   # NameError: name 'n' is not defined
```

名字查找按 **LEGB**：Local → Enclosing → Global → Built-in。
推导式自带作用域，而**类体不作为 Enclosing 层**出现在这条链上，`n` 只活在类的命名空间里，所以推导式找不到它。

- 对比：函数里的推导式能看到函数局部变量（函数是合法的 E 层），类不是。
- 唯一例外：最外层 `for ... in` 后面那个可迭代对象是在类体里求值的，能看到类变量（如 `[x * i for i in range(n)]` 里的 `range(n)` 成立）。
